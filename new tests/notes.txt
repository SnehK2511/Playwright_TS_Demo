============================================================
          PLAYWRIGHT TYPESCRIPT FRAMEWORK NOTES
============================================================

Purpose:
These notes explain the basic TypeScript concepts required
to understand and maintain a Playwright TypeScript framework.

============================================================
1. WHAT IS TYPESCRIPT?
============================================================

TypeScript (TS) is JavaScript with an additional feature
called "Type Checking".

In simple words:

JavaScript + Types = TypeScript

TypeScript helps us find many mistakes before running our
code.

Example:

JavaScript:

let age = 25;

TypeScript:

let age: number = 25;

Here, "number" tells TypeScript that age should contain
a number.


============================================================
2. WHY DO WE NEED TYPESCRIPT IN PLAYWRIGHT?
============================================================

TypeScript is useful in Playwright because it helps us:

1. Find mistakes early.
2. Understand what type of data a variable contains.
3. Write cleaner code.
4. Get better suggestions in VS Code.
5. Maintain large automation frameworks easily.
6. Reduce mistakes while working with Page Objects.
7. Understand function parameters and return values.

Example:

constructor(page: Page)

Here TypeScript tells us:

"page should be a Playwright Page."


============================================================
3. JAVASCRIPT vs TYPESCRIPT
============================================================

JavaScript:

function login(username, password) {
    // code
}


TypeScript:

function login(username: string, password: string) {
    // code
}


Main Difference:

JavaScript:
- Does not require types.
- Type checking is not built into the language.

TypeScript:
- Supports types.
- Finds many type-related errors before execution.
- Gives better editor support.
- Makes large projects easier to maintain.


Easy Example:

JavaScript:

let age = 25;
age = "Hello";

JavaScript allows this.


TypeScript:

let age: number = 25;
age = "Hello";

TypeScript shows an error because age should be a number.


============================================================
4. HOW DOES TYPESCRIPT WORK?
============================================================

TypeScript files use:

.ts

Example:

login.ts

The TypeScript compiler converts TypeScript into
JavaScript.

Flow:

TypeScript (.ts)
       |
       ↓
TypeScript Compiler (tsc)
       |
       ↓
JavaScript (.js)
       |
       ↓
Run the JavaScript


Important:

Browsers and Node.js normally execute JavaScript.

TypeScript is mainly used during development to provide
type checking and better tooling.

============================================================
6. WHAT IS tsconfig.json?
============================================================

tsconfig.json contains TypeScript configuration.

It tells TypeScript how our project should be checked
and compiled.

Example:

{
    "compilerOptions": {
        "target": "ES2022",
        "strict": true
    }
}


Important options:

target
→ JavaScript version to generate.

strict
→ Enables stronger TypeScript checking.

noEmit
→ Check TypeScript without creating JavaScript files.

include
→ Files that TypeScript should check.

exclude
→ Files that TypeScript should ignore.

12. IMPORTANT: PAGE vs LOCATOR
============================================================

In Playwright TypeScript:

Page

means the Playwright browser page.

Example:

page: Page;


Locator

means an element locator.

Example:

username: Locator;


Example:

import { Page, Locator } from '@playwright/test';

export class LoginPage {

    page: Page;
    username: Locator;

    constructor(page: Page) {

        this.page = page;

        this.username =
            page.locator('#username');
    }
}


Easy way to remember:

Page
→ Browser page/tab

Locator
→ Element on the page


============================================================
13. TYPESCRIPT DATA TYPES
============================================================

1. STRING
------------------------------------------------------------

Used for text.

Example:

let name: string = "Sneh";


2. NUMBER
------------------------------------------------------------

Used for numbers.

Example:

let age: number = 25;


3. BOOLEAN
------------------------------------------------------------

Used for true or false.

Example:

let isLoggedIn: boolean = true;


4. ARRAY
------------------------------------------------------------

Used to store multiple values.

Example:

let browsers: string[] = [
    "Chromium",
    "Firefox",
    "WebKit"
];


5. OBJECT
------------------------------------------------------------

Used to store related information.

Example:

let user: {
    name: string;
    age: number;
} = {
    name: "Sneh",
    age: 25
};


6. TUPLE
------------------------------------------------------------

Tuple stores values in a fixed order and type.

Example:

let user: [string, number] = [
    "Sneh",
    25
];

Position 0 → string
Position 1 → number


7. ANY
------------------------------------------------------------

any can contain almost any value.

Example:

let data: any = "Hello";

data = 100;
data = true;


Avoid using any unless it is really required because
it reduces TypeScript's type checking.


8. UNKNOWN
------------------------------------------------------------

unknown means:

"We don't know the type yet."

Example:

let data: unknown = "Hello";


Before using it as a specific type, check the type.


9. VOID
------------------------------------------------------------

Used when a function does not return a value.

Example:

function printName(name: string): void {

    console.log(name);
}


10. NEVER
------------------------------------------------------------

Used when a function never successfully finishes.

Example:

function errorMessage(): never {

    throw new Error("Something went wrong");
}


============================================================
14. VARIABLES
============================================================

let

Used when the value can change.

Example:

let age: number = 25;

age = 30;


const

Used when the variable should not be reassigned.

Example:

const name: string = "Sneh";


Easy rule:

let
→ Value can change.

const
→ Variable cannot be reassigned.


============================================================
15. FUNCTIONS IN TYPESCRIPT
============================================================

Basic format:

function functionName(
    parameter: type
): returnType {

}


Example:

function add(
    a: number,
    b: number
): number {

    return a + b;
}


Calling:

console.log(add(10, 20));


Result:

30


============================================================
16. OPTIONAL PARAMETERS
============================================================

Use ? when a parameter is optional.

Example:

function login(username?: string) {

    console.log(username);
}


username can be:

string

OR

undefined


============================================================
17. DEFAULT PARAMETERS
============================================================

Example:

function openBrowser(
    browser: string = "chromium"
) {

    console.log(browser);
}


If no value is provided:

openBrowser();


Chromium will be used.


============================================================
18. UNION TYPES
============================================================

Union means a value can have more than one allowed type.

Example:

let id: string | number;


Both are allowed:

id = "ABC123";

id = 100;


But:

id = true;

will give an error.


============================================================
19. OPTIONAL OBJECT PROPERTY
============================================================

Example:

type User = {

    name: string;

    phone?: string;
};


phone is optional.


============================================================
20. TYPE ALIAS
============================================================

A type alias gives a name to a type.

Example:

type User = {

    username: string;

    password: string;
};


Now we can use:

let user: User = {

    username: "Sneh",

    password: "12345"
};


============================================================
21. INTERFACE
============================================================

Interface is commonly used to define the structure of
an object.

Example:

interface User {

    username: string;

    password: string;
}


Use:

const user: User = {

    username: "Sneh",

    password: "12345"
};


Easy meaning:

Interface
→ Defines what properties an object should have.


============================================================
22. TYPE vs INTERFACE
============================================================

Both can describe object structures.

Example:

type User = {

    name: string;
};


interface User {

    name: string;
}


For beginners:

interface
→ Often used for object/class contracts.

type
→ Very flexible and can also create unions and other types.


============================================================
23. TYPE ASSERTION
============================================================

Type assertion tells TypeScript:

"I know what type this value is."


Example:

const value: unknown = "Hello";

const text = value as string;


Important:

Type assertion does NOT convert the actual value.

Example:

"123" as number

does not convert a string into a number.

For actual conversion:

Number("123");

============================================================
25. ACCESS MODIFIERS
============================================================

public

→ Can be accessed from outside the class.

private

→ Can be used only inside the class.

protected

→ Can be used inside the class and child classes.

readonly

→ Value cannot be reassigned after initialization.


Example:

class User {

    public name: string;

    private password: string;

    readonly id: number;
}


============================================================
26. TYPESCRIPT IN PAGE OBJECT MODEL
============================================================

A Page Object contains:

1. Page
2. Locators
3. Methods


Example:

import { Page, Locator } from '@playwright/test';

export class LoginPage {

    page: Page;

    username: Locator;

    password: Locator;

    loginButton: Locator;


    constructor(page: Page) {

        this.page = page;

        this.username =
            page.locator('#username');

        this.password =
            page.locator('#password');

        this.loginButton =
            page.locator('#login');
    }


    async login(
        username: string,
        password: string
    ): Promise<void> {

        await this.username.fill(username);

        await this.password.fill(password);

        await this.loginButton.click();
    }
}


============================================================
27. WHY DO WE USE Promise<void>?
============================================================

Playwright actions are asynchronous.

Example:

async login(): Promise<void>


Meaning:

Promise
→ The function completes asynchronously.

void
→ The function does not return a useful value.


Example:

async clickLogin(): Promise<void> {

    await this.loginButton.click();
}

29. PHONE NUMBER SHOULD BE STRING
============================================================

Phone numbers are usually better stored as strings.

Not recommended:

mobile: number;


Better:

mobile: string;


Example:

const mobile: string = "9876543210";


Why?

Because a phone number is an identifier, not a number
that we normally calculate with.

It can also contain:

+
spaces
country codes
leading zeros


============================================================
30. COMMON TYPESCRIPT + PLAYWRIGHT MISTAKES
============================================================

Mistake 1:

Selected = Locator;


Correct:

selected: Locator;


Reason:

Locator is a type.

We use:

propertyName: Type


------------------------------------------------------------

Mistake 2:

this.registerUrl =
    await page.click(...);


Wrong because:

page.click() returns Promise<void>.

Correct:

this.registerUrl =
    page.locator(...);

await this.registerUrl.click();


------------------------------------------------------------

Mistake 3:

mobile: number


Better:

mobile: string


------------------------------------------------------------

Mistake 4:

Expecting a string to be visible:

expect(confirmationText).toBeVisible();


If confirmationText is a string, it is not a Locator.

Correct:

await expect(
    page.getByText(confirmationText)
).toBeVisible();

37. MOST IMPORTANT INTERVIEW ANSWERS
============================================================

Q: What is TypeScript?

A:
TypeScript is JavaScript with a type system. It helps us
find many errors during development before the code runs.


Q: Why use TypeScript with Playwright?

A:
It provides type checking, better VS Code support and makes
large automation frameworks easier to maintain.


Q: What is the difference between JavaScript and TypeScript?

A:
JavaScript does not require type annotations, while
TypeScript provides static type checking and is normally
compiled/transformed to JavaScript.


Q: What is tsc?

A:
tsc is the TypeScript compiler.


Q: What is tsconfig.json?

A:
It contains TypeScript compiler and project settings.


Q: What is an interface?

A:
An interface defines the structure or contract of an object.


Q: What is a union type?

A:
It allows a variable to have one of multiple types.

Example:

string | number


Q: What is any?

A:
any allows almost any value and reduces type checking.
It should be avoided when a better type is available.


Q: What is unknown?

A:
unknown means the type is not known yet. We should check
the type before using the value.


Q: How do you type a Playwright Page?

A:

page: Page


Q: How do you type a Playwright Locator?

A:

button: Locator


Q: How do you check TypeScript errors?

A:

npx tsc --noEmit
